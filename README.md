## Website Development

This repository also powers [www.shreejitverma.com](https://www.shreejitverma.com/) (Next.js 16, Tailwind CSS v4, deployed on Vercel).

```bash
npm run dev          # local dev server
npm run build        # production build
npm run lint         # ESLint
npm run typecheck    # TypeScript strict check
npm run test:e2e     # full Playwright E2E suite (desktop + mobile)
```

The E2E suite (`e2e/`) covers every public page; `e2e/README.md` lists what each spec checks.
CI runs lint, typecheck, and the full suite on every pull request (`.github/workflows/e2e.yml`).
`scripts/enrich_books.py` enriches the reading-list dataset with cover images and descriptions from Open Library and Google Books; it is resumable and idempotent.
`scripts/import_vault_covers.py` imports curated covers from the Obsidian vault (`Reading/Library/` notes and `Attachments/Covers/`) as 320px WebP files under `public/covers/`, matching books by title and author and never guessing: ambiguous matches, generated title-card covers, and titles listed in `scripts/cover_overrides.json` are skipped.
Adding a title to that skip list also clears a vault cover it already received, so `enrich_books.py` fetches a hotlinked one on its next run.
Vault covers take precedence over the hotlinked covers from `enrich_books.py`, which never overwrites an existing cover; rerun the import after adding books or covers to the vault (`python3 scripts/import_vault_covers.py --dry-run` previews the changes).
`scripts/make_icons.py` renders the "SV" monogram site icons (`app/favicon.ico`, `app/icon.png`, `app/apple-icon.png`); rerun it with `uv run --with pillow python3 scripts/make_icons.py` after changing the theme's primary color.
`.github/workflows/metrics.yml` refreshes the GitHub Impact cards daily and publishes them to the `output` branch: `scripts/github_stats.py` writes `github-stats.json` (rendered natively on the home page), `scripts/github_cards.py` draws the README's stats and language cards from it, and `python3 -m unittest discover -s scripts/tests` tests both.
`scripts/categorize_books.py` assigns book categories through hand-curated overrides (`scripts/category_overrides.json`), title-family regex rules, and ordered keyword rules, keeping the `General` shelf a small miscellany bucket.
`scripts/` also holds standalone personal data tooling unrelated to the site, such as `scripts/amazon_ir_scraper.py`, which downloads Amazon investor-relations PDFs (annual reports, proxy statements, shareholder letters) into `~/Downloads/Amazon_IR_Documents`.
`backlog.md` is the workspace task backlog managed by `tasks-axi`.

### Agent access

The site is built to be read and used by AI agents, and scores Level 5 ("Agent-Native") on Cloudflare's [Agent Readiness scanner](https://isitagentready.com).
Everything is public, read-only, and unauthenticated, and every surface answers from the same data as the pages (`app/lib/profile.ts`, `app/lib/writing.ts`, `app/lib/agent/pages.ts`).
The code lives in `app/lib/agent/`; `e2e/agent-ready.spec.ts` covers each endpoint.

| Surface | Where | Notes |
| --- | --- | --- |
| Markdown for agents | any page with `Accept: text/markdown`, or `/index.md`, `/resume.md`, ... | Converted from the page's own rendered `<main>`, so it never drifts from the HTML; sends `x-markdown-tokens` and `Content-Signal` |
| `llms.txt`, `llms-full.txt` | `/llms.txt`, `/llms-full.txt` | Generated from the profile and page list |
| Crawler policy | `/robots.txt` | Content Signals `search=yes, ai-input=yes, ai-train=yes` plus explicit AI search, user-triggered, and training crawler groups (`CONTENT_SIGNAL` in `app/lib/agent/constants.ts`) |
| MCP server | `/mcp` (streamable HTTP, stateless) | Nine read-only tools: profile, experience, projects, education, skills, search, JSON Resume, page list, page as Markdown; Server Card at `/mcp/server-card` |
| A2A agent | `/a2a` (JSON-RPC, protocol 1.0 and 0.3) | Deterministic retrieval, no LLM; Agent Card at `/.well-known/agent-card.json` |
| WebMCP | inline `<head>` script | Registers five in-browser tools before `load` |
| REST | `/resume.json` (JSON Resume), `/api/search?q=` | Described by `/openapi.json` |
| Discovery | `/.well-known/api-catalog` (RFC 9727), `/.well-known/ai-catalog.json`, `/.well-known/agent-skills/index.json`, `/.well-known/did.json`, `/.well-known/poppy.json`, `Link` response headers | Catalogs point at each other and at every endpoint above |

Markdown is fetched from this same deployment and converted per request (`app/lib/agent/markdown.ts`), so a Markdown response is marked `private`: the same URL serves HTML to browsers.
If the Cloudflare proxy is enabled, the Vercel function's self-fetch of the canonical origin must be exempted from bot protection (for example with a WAF skip rule), otherwise the Markdown endpoints return 502.
Adding a page to `SITE_PAGES` in `app/lib/agent/pages.ts` adds it to the sitemap, `llms.txt`, the Markdown rewrites, and the agent tools at once.

### Agent authentication

A recruiter's AI agent can send Shreejit a job opportunity, but only after a person approves it; everything else stays public.
The code is in `app/lib/auth/`, `app/lib/opportunities.ts`, and `app/lib/agent/web-bot-auth.ts`; `e2e/agent-auth.spec.ts` drives every flow end to end.

| Piece | Where | Standard |
| --- | --- | --- |
| Authorization server metadata | `/.well-known/oauth-authorization-server` | RFC 8414, plus the auth.md `agent_auth` block |
| Protected resource metadata | `/.well-known/oauth-protected-resource[/mcp/recruiter, /api/opportunities]` | RFC 9728 |
| Client registration, authorize, token, revoke, JWKS | `/oauth/register`, `/oauth/authorize`, `/oauth/token`, `/oauth/revoke`, `/oauth/jwks.json` | RFC 7591, OAuth 2.1 with mandatory S256 PKCE (RFC 7636), RFC 9207, RFC 7009, RFC 7517 |
| Agentic registration and claim | `/agent/identity`, `/agent/identity/claim`, `/claim`, `/auth.md` | [auth.md](https://workos.com/auth-md) (anonymous identity only) |
| Protected endpoints | `POST /api/opportunities`, MCP at `/mcp/recruiter` (`send_opportunity`, `whoami`) | Bearer tokens (RFC 6750), audience-bound (RFC 8707) |
| Web Bot Auth | `/.well-known/http-message-signatures-directory`; the Markdown fetcher signs its requests | RFC 9421, Ed25519 |

Access tokens are EdDSA JWTs (RFC 9068) that last 15 minutes; codes and refresh tokens are single use, enforced by an atomic read-and-delete.
Claiming an auth.md registration or revoking a grant takes effect immediately, because the resource server checks the grant behind every token.
Each submission becomes an issue in the private repo `shreejitverma/opportunities`, with all submitted text fenced so it cannot inject Markdown or mentions; each approval may send 3 per day, and all agents together 30.

Configuration (Vercel, all environments).
On Vercel a missing or unusable key fails closed: auth endpoints answer 503, while the Markdown fetcher logs signing failures and sends unsigned requests.
PKCS#8 values are normalized when pasted from environment variable UIs, including quoted values, escaped or flattened newlines, and a shell prompt line; values without usable key material return 503.
Off Vercel the keys are generated per process and state lives in memory, so local runs and the e2e suite need nothing.

| Variable | Value |
| --- | --- |
| `AUTH_SIGNING_KEY` | Ed25519 private key, PKCS#8 PEM (`openssl genpkey -algorithm ed25519`); signs tokens |
| `WEB_BOT_AUTH_KEY` | A second, separate Ed25519 key in the same format; signs outbound bot requests, with unsigned fallback on signing failure |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | Upstash Redis from the Vercel Marketplace (set automatically when connected) |
| `GITHUB_OPPORTUNITIES_TOKEN` | Fine-grained token with Issues read and write on `shreejitverma/opportunities` only |

To rotate a key, replace the variable and redeploy: outstanding access tokens and identity assertions stop verifying, and agents re-authenticate.
Because state is in memory locally, `npm run test:e2e` needs a fresh server; reusing one across many runs eventually hits the 30-per-day submission cap by design.

### Search visibility

- Structured data (`app/lib/structured-data.ts`) is derived from `app/lib/profile.ts`, so search engines and AI assistants see the same employer, titles, and degrees as readers; `ProfilePage` is declared only on `/` and `/resume`.
- `.github/workflows/indexnow.yml` submits every sitemap URL to IndexNow (Bing, which also backs ChatGPT search and Copilot, plus Yandex, Seznam, Naver, and Yep) after each successful production deployment; `python3 scripts/indexnow.py --dry-run` previews the payload.
- The sitemap sets `lastmod` only from real dates (article publication), never the build time, so search engines can trust it.
- Agent and discovery endpoints send a strong `ETag` and answer a matching `If-None-Match` with `304 Not Modified`, so revalidating crawlers transfer nothing.
- `/feed.xml` is an Atom feed of the articles, linked from every page and from `llms.txt`.
- URLs from earlier versions of the site, including old resume PDF paths, permanently redirect to their current pages (`LEGACY_REDIRECTS` in `next.config.ts`), so their ranking signals carry over instead of ending in a 404.
