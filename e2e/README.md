# End-to-End Test Suite

Playwright suite that exercises every public surface of the website.
`playwright.config.ts` builds and serves a production build (`npm run build && npm run start`) on `http://localhost:3000` automatically before the tests run.

## Running locally

```bash
npx playwright install chromium   # one-time browser install
npm run test:e2e                  # full suite
npm run test:e2e:ui               # interactive UI mode
```

Every spec runs on two device profiles: `desktop` (Desktop Chrome) and `mobile` (Pixel 7).
Pixel 7 is a Chromium device profile, chosen so CI only needs the chromium browser.
Test artifacts (`test-results/`, `playwright-report/`, `blob-report/`, `playwright/.cache/`) are gitignored.

| `resume-page.spec.ts` | `/resume` states name, roles, and location; PDF download and contact links; every resume section; all six employment entries in order (current Barclays role first); linked finance and CS certifications; headline quantitative achievements |
| `navigation.spec.ts` | Desktop nav anchors target existing sections, mobile hamburger menu open/navigate/close with `aria-expanded`, theme toggle, `dark:` utilities following the site theme rather than the OS color scheme, desktop nav links to `/value-investing` and `/books`, cross-page navigation |
| `github-stats.spec.ts` | `parseGitHubStats` accepts the shape `scripts/github_stats.py` writes, drops unknown fields, and rejects missing, negative, fractional, or non-numeric counts, language shares that are empty, malformed, or do not sum to 1, an unparseable timestamp, and non-objects.<br>`statTiles` words pull requests, issues, stars, forks, and code reviews with correct singulars, and omits code reviews when there are none. |

| `books.spec.ts` | `/books` library behavior: initial load with a full first page and total count, debounced search by title or author, definitive empty state, category filter resetting to page 1, data-driven category pills whose counts match the dataset, numbered pagination (Previous/Next plus a direct jump to the last page), every card offering a `Find on Amazon` link and none linking into the unserved `/library/` or `/content_library/` paths, page changes scrolling back to the top of the results, content painting above the fixed background canvas, meaningful image alt text; dataset quality gates: every book has a title and a description or review, cover URLs are well-formed, every self-hosted `/covers/` image the dataset references (imported from the Obsidian vault) is served as WebP, the shelves are exactly the expected ten categories with General kept under 150 books, and over 40% of books have real covers |

| `a11y.spec.ts` | axe WCAG 2 A/AA scan on every page in both the dark and light site themes; serious and critical violations fail the test |
| `agent-ready.spec.ts` | Agent access: every page returns Markdown for `Accept: text/markdown` and at its `.md` URL (canonical `Link`, token count, Content-Signal, absolute links, no HTML), browsers still get HTML with discovery `Link` headers and the Next.js `Vary` list intact, static files ignore the Markdown Accept header, unknown pages get a Markdown 404, pages advertise their Markdown twin in `<head>`; robots.txt Content Signals and AI crawler groups; `llms.txt` and `llms-full.txt`; MCP Server Card, A2A Agent Card (v1.0 and v0.3 interfaces), RFC 9727 API catalog, AI Catalog, and Agent Skills documents including link resolution and SHA-256 digests, with only listed skills served (inherited object keys such as `constructor` 404); Personal Agent Protocol manifest; JSON Resume dates; search ranking for natural-language queries; MCP initialize, `tools/list`, and `tools/call`; A2A `SendMessage` (v1.0) and `message/send` (v0.3), a very long message answered quickly with the echoed query bounded to 200 characters, and a non-object JSON body rejected with `-32600`; WebMCP tools registered by the `load` event and executable |
| `agent-auth.spec.ts` | Agent authentication against the specs, not the implementation: RFC 8414 and 9728 metadata and the auth.md `agent_auth` block, JWKS without private parts, 401 challenges carrying `resource_metadata`; the authorization-code flow in a real browser (consent, RFC 9207 `iss`, PKCE computed per RFC 7636, single-use codes burned on a failed verifier, MCP `whoami` and REST submission, refresh rotation, revocation that kills live access tokens), mismatched redirect URIs shown instead of followed, missing PKCE and denial returned to the client, anti-framing and no-store headers, per-IP registration rate limits and unsafe redirect URIs refused; auth.md anonymous registration that can read but not submit until a person claims it on the claim page, pre-claim tokens revoked by the claim, five wrong codes burning the attempt, unsupported identity types; per-approval daily submission cap and RFC 8707 audience enforcement; a signed Web Bot Auth key directory and request signatures verified with Cloudflare's `web-bot-auth` library |
| `crawl.spec.ts` | Crawl efficiency: sitemap `lastmod` only on dated pages and equal to the publication date, `ETag` revalidation with `304` and no body (including weak `If-None-Match` forms) on agent endpoints, no validator on error responses, and a well-formed Atom feed listing every article newest first, advertised on every page |
| `legacy-urls.spec.ts` | URLs from earlier versions of the site (old `.html` pages and resume PDF paths) answer with permanent redirects to their current pages, Google and Yandex HTML verification files (`google<hex>.html`, `yandex_<hex>.html`) are exempt from the catch-all `.html` redirect, the old resume path serves the current PDF, and `ProfilePage` JSON-LD appears on `/` and `/resume` only |
| `console-health.spec.ts` | Every page returns 200 and produces no console errors or page crashes |

`helpers.ts` defines the page list with expected canonicals and the console-error filter: identifiable third-party noise and third-party resource-load failures are ignored, while same-origin failures (except Vercel-injected `/_vercel/` analytics scripts, which 404 under local `next start`) fail the suite.

## CI

`.github/workflows/e2e.yml` runs two jobs on pull requests and pushes to `main`: a `quality` job (`npm run lint` and `npm run typecheck`) and the `e2e` job with the full suite.
On failure it uploads the HTML report as the `playwright-report` artifact (14-day retention).
